# 棱镜原生漏洞扫描

## 产品方向与当前实现

参考 Nuclei 的声明式检测规则、组合匹配，以及 Nessus 的策略、任务、漏洞管理和历史对比设计。检测器、规则格式、任务调度和界面由棱镜自行实现；扫描无需 Nuclei/Nessus 二进制、NASL、Nuclei YAML、MCP 连接或模型密钥。未复制 Nessus 专有代码或规则库。

公开设计参考：

- [Nuclei 模板结构](https://docs.projectdiscovery.io/templates/introduction)
- [Nuclei 匹配器](https://docs.projectdiscovery.io/templates/reference/matchers)
- [Nessus 扫描策略](https://docs.tenable.com/nessus/Content/Policies.htm)
- [Nessus 扫描结果与历史](https://docs.tenable.com/nessus/Content/ScanResults.htm)

这是原生扫描的第一版，不宣称覆盖两者全部功能。当前已实现：

- 匿名 HTTP/HTTPS GET 探测、TLS 证书检查，快速、标准、自选规则三种策略。
- 原生 TCP Connect 端口扫描：IP/域名、端口列表与范围、并发和超时控制、端口状态、历史对比、后续 Web 检查与报告。
- 独立端口指纹漏洞扫描：实际协议响应识别、五条协议/证书风险规则、服务结果与漏洞发现分开显示。
- 17 条原创规则：MIME 嗅探防护、页面嵌入策略、CSP、HSTS、Cookie 属性、Git/SVN 元数据暴露、目录索引、PHP 诊断页面、应用环境端点、监控指标、TLS 信任链/域名/有效期/RSA 公钥检查。
- 条件组合、状态码、响应头、正文标记、Cookie 属性、TLS 属性匹配；自定义 JSON 规则导入和版本管理。
- PostgreSQL 持久化任务与规则快照，顺序队列、进度、暂停、继续、取消；重启后标记中断，必须手动继续。
- 发现列表、风险筛选、检测依据、修复建议、误报/接受风险处置、复测任务、历史对比、HTML/JSON 报告。
- 用户隔离与可选项目协作；独立扫描不创建项目或 DSH 会话。

尚未实现：UDP/SYN 扫描、CIDR 网段展开、完整产品指纹/CVE 数据库、DNS/SMB 等其他协议漏洞检查、登录态 Web 扫描、SSH/SMB 主机认证检查、补丁与合规审计、计划扫描、分布式执行器。这些属于后续原生检测能力，不以安装或调用第三方扫描器代替。

## 使用

Compose 启动后，点击左侧「安全工具」展开子菜单，再进入「漏洞扫描」或「工具集成」。进入子页面或刷新其直达链接时，该分组自动展开；手动收起不会改变当前页面。

新建扫描提供三个独立类型：

| 类型             | 输入                        | 结果                                        |
| ---------------- | --------------------------- | ------------------------------------------- |
| 网络端口扫描     | IP/域名与端口列表或范围     | TCP 开放、拒绝、未确定状态；不产生漏洞发现  |
| 端口指纹漏洞扫描 | IP/域名、端口与探测方式     | 实际协议指纹、声明版本、协议/配置风险与证据 |
| Web 漏洞扫描     | HTTP(S) URL 与 Web 规则策略 | Web 暴露、配置、TLS 检查及漏洞处置          |

三种任务均可独立使用，不要求先创建项目或先执行其他扫描。各类型保留本页草稿，历史记录可以按类型筛选。

选择「Web 漏洞扫描」，输入一至二十个 HTTP(S) URL，每行一个，选择策略，点击「开始扫描」。例如指定 `/app/` 时，只请求该路径及规则定义的下级路径；不会自动扩大到站点其他路径。需检测重定向目的地时，应直接填入最终 URL。

「复测」会预填相同目标与规则 ID，提交前可调整。任务保存当次规则快照；自定义规则更新后，新任务使用新版本。只有相同归属、目标集合和规则快照的任务才能对比。项目协作者可以对比同项目的记录；独立任务须属于同一用户。

报告中的「复测未命中」必须有相应规则实际成功完成。连接失败、超时、重定向、响应被截断或不支持的内容编码不会被视为修复。信息等级的 CSP、SameSite 等项目属于加固建议；命中也不等同于已利用成功。

任务工作台里的「分析已有证据」仍使用 DSH Agent；它不会替代本页的网络扫描。

扫描记录可按名称或目标搜索，并结合 Web/TCP 类型、任务状态筛选。Web 与 TCP 表单分别保留本页内的名称、目标、超时和间隔；切换类型不会清空输入，刷新页面后草稿清除。点击新建、复测或端口后续检查，会定位到表单并聚焦目标输入框。

运行中的任务约每 2.5 秒刷新；空闲时约每 30 秒更新，检测规则最多每 30 秒自动重读一次。页面进入后台后停止自动请求，回到前台立即刷新。提交操作会立即更新数据，并忽略操作前尚未返回的旧读取结果。

## TCP 端口扫描

新建扫描时选择「网络端口扫描」，目标填写 IP 或域名，不带 URL 协议、路径或端口。支持 IPv4、IPv6 和域名，每行一个。端口单独填写，例如 `22,80,443,8000-8100`，也可选常用端口或 `1–1024`。

- 可选择 1–65535 范围内的端口；每次任务最多 4096 个“目标 × 端口”组合。例如四台主机各扫描 1024 个端口；全端口扫描目前需要分批提交。
- 使用 Node 原生 TCP 连接，不调用 Nmap。每批最多 16 个并发连接，批次间隔至少 250 毫秒，连接超时 1–5 秒。每批开始前重新检查权限。
- 连接成功为「开放」，连接被拒绝为「关闭」；超时显示「超时 / 未确定」，DNS/地址策略/网络错误单独记录，不将这些情况判为关闭。
- 表格中的常见用途来自端口号映射，未主动验证实际协议或版本。开放端口不产生漏洞发现，也不会自动尝试登录或发送应用层探测内容。
- 暂停与取消会关闭正在连接的套接字；继续时跳过已持久化的结果。一次运行达到十分钟时限会标记中断，可以继续剩余探测。
- 同归属、同主机集合、同端口集合的历史扫描可以对比新增开放、仍开放、已关闭和未确定。只有复测明确拒绝连接才会标为已关闭。
- 对开放端口点击「HTTP 检查」或「HTTPS 检查」，会预填 Web 扫描表单；确认目标和策略后再点击开始，不会自动发起新检测。
- 可跨页勾选最多 20 个开放端口，选择 HTTP 或 HTTPS 后「批量 Web 检查」。本页全选最多补足 20 个，筛选与翻页保留选择，关闭或未确定端口不可选；只读用户不能发起后续检查。
- HTML/JSON 报告保存端口状态、解析地址与说明，不记录原始服务横幅。

## 端口指纹漏洞扫描

该类型独立于 TCP Connect 和 Web 规则引擎。可直接输入目标与端口，也可从网络端口结果点击「指纹漏洞检查」预填表单；不会自动启动后续探测。

- 自动模式：常用 HTTP 端口发送一次 `HEAD /`，常用 TLS 端口执行匿名 TLS 握手，6379 发送一次 `INFO server`；其他端口只读取问候语。端口号仅决定尝试哪种探测，不作为服务识别结果。非标准端口可明确选择 Redis、HTTP、TLS 或被动问候语。
- 被动识别 SSH、FTP、SMTP、MySQL 问候语；HTTP、Redis 和 TLS 按实际响应判断。只保存固定协议名、受限产品名、数字版本及检查结论，不保存原始问候语、服务信息、HTTP 头或证书正文。版本为服务自报，可能隐藏、伪造或包含发行版补丁，不能直接当作 CVE 证据。
- 五条内置协议规则：SSH 1.x/1.99 兼容声明、Redis 服务信息匿名可读、TLS 证书验证失败、证书过期、RSA 公钥不足 2048 位。Redis INFO 可读仅证明服务信息暴露，未推定数据库读写能力；不尝试认证、写操作或漏洞利用。
- 每次最多 128 个目标与端口组合，逐端口执行，间隔至少 250 毫秒，每端口绝对超时 1–15 秒，响应最多 8 KiB。沿用 DNS 地址检查与绑定、内网权限、用户/项目隔离和十分钟运行上限。
- 每个端口完成后保存进度，暂停/取消关闭连接，继续跳过已完成端口。未知服务、截断和失败显示为未完成；只有相同目标、端口、模式与协议规则快照可比较。连接失败或端口关闭不会被记作漏洞修复，必须有同一规则明确未命中的检查结果。
- 「检测规则」分别显示 Web JSON 规则和端口协议规则。当前端口规则为内置实现，不接受 Web JSON 规则或第三方模板导入。报告同时包含服务指纹、命中规则、处置及覆盖情况。

协议实现依据：[SSH 版本交换](https://datatracker.ietf.org/doc/html/rfc4253#section-4.2)、[Redis RESP](https://redis.io/docs/latest/develop/reference/protocol-spec/)、[Redis INFO](https://redis.io/docs/latest/commands/info/)、[MySQL 握手](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_connection_phase_packets_protocol_handshake_v10.html)、[SMTP](https://www.rfc-editor.org/rfc/rfc5321)、[FTP](https://datatracker.ietf.org/doc/html/rfc959)。

## 权限与运行边界

- `scan.run`：执行扫描，默认普通角色拥有。独立扫描还需 `task.use`；项目扫描还需该项目的执行权限。
- `scan.internal`：扫描 RFC1918 等内网地址，普通用户默认没有；可通过角色或用户单独授权。
- `scan.rules`：管理自定义规则，普通用户默认没有。
- 系统管理员可查看、管理所有扫描；项目查看者只读。每次 Web 请求或 TCP 批次前重新检查执行者权限，撤销权限会停止后续请求。
- 所有用户均禁止访问本机地址、回环、链路本地、组播和保留地址。DNS 结果全部通过检查后绑定其中一个地址，连接过程中不重新解析、不跟随重定向，不带认证头或 Cookie。
- 单个应用实例一个执行器，每用户最多三个等待/运行任务、全局队列最多一百个。Web 请求超时 1–15 秒，请求间隔至少 250 毫秒，单次运行最多十分钟，达到时限后可手动继续。响应头最多 16 KiB，正文最多 64 KiB。TCP 限制见上节。
- 原始响应正文、Cookie 值和证书原文不写入数据库；只保存有界规则依据与检查结果。规则不支持执行脚本、任意请求头、正则表达式或 shell。

这是用户直接操作的确定性扫描控制面，独立于模型工具调用。没有新增 Agent 循环、模型客户端或会话存储，也没有将 HTTP 控制面作为 Agent 绕过审批的入口。原有 DSH 工具调用继续经过 Harness 的沙箱、审批和范围检查。

当前部署为单个应用实例，不支持多个应用副本共享扫描队列。Compose 的数据库和数据卷沿用现有部署。

## 自定义规则

管理员可在「检测规则 → 添加或更新自定义规则」导入下列格式。自定义 ID 不可使用 `prism-` 前缀；覆盖同一 ID 必须增加版本号。响应内容只用于匹配，不会作为原始证据持久化。

```json
{
  "id": "company-public-diagnostics",
  "version": 1,
  "title": "公司诊断页面公开可读",
  "family": "exposure",
  "severity": "medium",
  "path": "diagnostics/status",
  "match": {
    "all": [
      { "field": "status", "op": "equals", "value": 200 },
      { "field": "body", "op": "contains", "value": "Company Diagnostic Console" }
    ]
  },
  "evidence": "无需认证即可读取带有诊断控制台标记的页面。",
  "remediation": "将诊断端点限制在管理网络内，并启用访问控制。"
}
```

字段支持 `status`、`header`、`body`、`cookie`、`tls.valid`、`tls.days`、`tls.keyBits`。操作符为 `equals`、`contains`、`absent`、`lt`；`header` 与 `cookie` 需提供小写 `key`。Cookie 当前仅支持缺失属性检测。`all` 和 `any` 支持最多三级嵌套。TLS 规则应使用 `family: "tls"`，HTTP 目标会跳过此类规则。

不要用响应中单个软件名称直接推定 CVE。具体漏洞规则应有充分且低影响的判断条件，并通过易受影响、修复和异常响应三个方向的测试。

## 验证

`tests/native-engine.spec.ts` 使用本机临时 HTTP/HTTPS 测试服务验证实际网络传输、DNS 地址绑定、重定向边界、超时、响应截断及证书检查；不扫描第三方网站。数据库测试覆盖用户/项目隔离、权限撤销、队列与生命周期、规则版本、结果处置和复测差异。页面测试覆盖独立发起扫描、策略、暂停继续、漏洞处置与导出。

`tests/native-ports.spec.ts` 使用本机临时 TCP 服务验证真实开放和关闭状态、不发送应用数据、地址限制、并发上限、取消与恢复、用户隔离和端口报告；模拟的超时与网络错误不会产生“端口关闭”的结论。页面测试覆盖端口扫描表单、状态筛选、分页、复测和 Web 后续表单。

`tests/native-services.spec.ts` 使用临时 TCP/TLS 服务测试分段响应、HTTP HEAD、Redis INFO、SSH 问候语、自签名证书、数据上限、超时、取消、DNS 限制、检查快照、权限隔离、复测与报告；测试不接触第三方目标。

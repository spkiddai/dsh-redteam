# 棱镜独立应用（开发中）

棱镜借鉴 DSH 的插件组合思路，但独立入口不加载 Cordis、DSH 客户端或 DSH Agent。
当前仓库同时保留旧版适配器，便于在迁移期间继续使用原有功能。默认 `compose.yml`
仍运行旧版；仓库改名不等于全部功能迁移完成。

## 启动

使用 Node.js 24 与仓库声明的 pnpm 版本：

```bash
pnpm install
pnpm build:standalone
PRISM_PORT=3081 pnpm start:standalone
```

打开 `http://127.0.0.1:3081/`，空数据库首次启动会创建 `admin/admin`。
初始密码仅提示修改；新密码要求 8–128 位。

- `PRISM_HOME`：独立版数据目录，默认 `~/.prism-app`。
- `PRISM_PROJECT_ROOT`：项目工作目录，默认位于 `PRISM_HOME/projects`。
- `PRISM_DATABASE_URL`：可选 PostgreSQL 连接字符串；未设置时使用 PGlite。
- `PRISM_HOST`：默认 `127.0.0.1`；容器环境可设为 `0.0.0.0`。
- `PRISM_PORT`：默认 `3080`；与旧版同时试用时选择其他端口和独立数据库。
- `PRISM_ORIGIN`：外部访问的完整 HTTP(S) 源地址，用于 Host / Origin 检查。

不要同时运行两个共享同一扫描数据库的服务实例。服务重启会将未完成任务标为中断，
需要操作者明确继续，不会自动重新发送扫描请求。

## 已实现与待迁移能力

| 能力                                       | 独立版状态                             |
| ------------------------------------------ | -------------------------------------- |
| 登录、用户管理、角色与单独授权             | 已接入原数据库权限模型                 |
| 项目资源授权                               | 可选关联，独立任务无需项目             |
| 网络端口、端口指纹漏洞、Web 扫描           | 已接入原扫描引擎、队列、报告与复测     |
| 资产台账                                   | 可登记来源与说明，按用户或项目隔离     |
| 插件注册                                   | 依赖排序、重复检查、动作分发、逆序清理 |
| 外部 MCP 工具、AI Agent 对话与自动资产发现 | 尚未迁移，页面明确提示不可用           |
| 旧会话、旧资产图                           | 原数据保留，尚未自动导入               |

## 代码边界

- `src/server/main.ts`：独立进程入口，配置、启动和信号退出。
- `src/server/http.ts`：登录、HTTP API、来源检查和静态页面，不代理 DSH。
- `src/server/plugins.ts`：可信代码插件的生命周期与动作注册表；不接受网页上传代码执行。
- `src/server/app.ts`：组合身份权限、内置扫描和资产台账插件。
- `src/lib`：可复用的数据库、权限与扫描逻辑。
- `src/client/standalone`：独立 React 页面，安全工具是独立模块，下设内置扫描和工具集成。
- `src/plugins`、`src/client/index.tsx`：保留的旧 DSH 适配层。

插件通过 `setup(context)` 注册具名动作与 `dispose()` 清理函数，依赖不满足或循环依赖会启动失败。
HTTP 入口统一鉴权，动作仍须检查自身资源权限。插件注册仅来自服务端可信代码，
并不把外部工具输出当作配置或指令。

# 数据库与 Docker Compose 部署

## 启动

在项目根目录执行：

```bash
node scripts/prepare-compose.mjs
docker compose up -d --build
docker compose ps
```

准备脚本以 0600 权限创建 `.env`，生成随机数据库密码，不打印密码、不覆盖现有文件。
已有 `.env` 时请设置 `PRISM_DB_PASSWORD`，推荐使用 64 位随机十六进制字符串，避免连接 URL 的保留字符。

打开 <http://127.0.0.1:3080/>，默认管理员为 **admin / admin**，登录后直接进入工作台，仅提示建议修改初始密码；可关闭提示。设置或重置密码要求 8–128 位，默认 admin/admin 可直接使用。
初始管理员仅在空数据库创建；重启不会重置密码。没有自助注册入口，在独立“用户管理”页面添加、编辑和停用账号，在“权限管理”分配角色和用户例外。

Compose 包含棱镜和 PostgreSQL 18，数据库不映射宿主机端口。棱镜依赖数据库健康检查，通过 `PRISM_DATABASE_URL` 连接，数据库不可用时拒绝访问，不会退回空数据库。
本地 Node 开发未配置该环境变量时使用持久化 PGlite（嵌入式 PostgreSQL），目录为 `accountRoot/database`。
两者采用同一 SQL 模型，但数据目录不能直接互换；生产部署使用 Compose PostgreSQL。

DSH 固定 `0.2.1-rc.2`，插件 `1.4.0`。构建需要 Docker Hub、Debian 和 npm 软件源。容器以普通用户运行，没有 Docker Socket 或 privileged 配置。

## 角色与资源权限

用户独立存在，可以没有项目、同时拥有多个角色。角色授予通用权限，用户例外允许单独增加或明确拒绝；项目是资源类型之一。详见 [权限模型](permissions.md)。

四个功能模块可直接进入，不需要先创建项目。默认独立任务按账号保存，系统自动处理原生会话；在模块顶部选择项目即可切换资源范围。“使用独立任务”与项目权限分别控制，独立记录仅本人及管理员可访问。

| 权限           | 范围与行为                                                       |
| -------------- | ---------------------------------------------------------------- |
| 创建项目       | 系统功能；创建后获得该项目的显式管理授权，可撤销                 |
| 查看项目       | 指定项目或全部项目；读取会话和报告                               |
| 执行评估       | 包含查看；创建会话、执行、取消和审批任务                         |
| 管理项目       | 包含执行；修改项目执行策略，不包含给用户授权                     |
| 管理用户       | 创建普通账号、编辑、停用、重置密码；不能单凭此权限授予管理员身份 |
| 管理角色与授权 | 编辑角色、分配用户角色和用户例外                                 |
| 配置工具连接   | 管理主机 MCP 连接；仍受工具确认和 DSH 原生审批约束               |

系统管理员固定拥有完整权限，不能移除最后一位启用的管理员。普通用户默认角色授予独立任务使用和创建项目。明确拒绝优先于角色和用户的允许；拒绝项目读取也阻止执行和管理。项目创建者只作为元数据，不能绕过权限检查。

旧项目归属和成员授权在首次升级时转换为显式权限，此后不会在重启时恢复已撤销的授权。用户权限在服务端 HTTP、原生 Remote 调用和 WebSocket 流上检查，前端隐藏按钮不是权限边界。项目未授权时不能读取其会话；未登记归属的旧 DSH 会话不会自动暴露。

密码使用随机盐和 scrypt 哈希；登录令牌只以 SHA-256 摘要保存于数据库，8 小时过期。修改密码、停用用户、调整角色撤销相关登录令牌；授权变化关闭现有传输连接并重新计算原生权限。项目、用户授权修改有数据库审计记录，不记录密码、令牌或会话正文。

DSH 仍独占模型、聊天历史、工具及审批引擎。当前是单棱镜实例，不能通过增加副本获得多实例一致性。

## 执行隔离范围

DSH 文件沙箱限制写入，不能充当租户之间的文件读取隔离。普通用户的独立任务，以及普通用户具备执行权限的项目，只开放棱镜结构化工具、内置受控安全工具及原生问答/计划审批；任意 Shell、PTC 脚本、主机文件工具和未受控扩展在工具执行入口被拒绝。知识库也按工作区独立存储，不使用全局 Graphiti/RAGFlow 资料。

仅管理员可执行的私有项目保留原生工具，继续受 DSH 沙箱和审批控制。要给普通用户开放任意命令，需要后续部署独立项目执行容器/远程执行器；当前版本没有实现该隔离执行层，不能宣称等同于 Strix 的完整自主测试能力。

## 数据与导入

| 命名卷         | 路径                             | 内容                                               |
| -------------- | -------------------------------- | -------------------------------------------------- |
| prism-db       | PostgreSQL `/var/lib/postgresql` | 用户、角色、用户例外、登录令牌摘要、会话归属、审计 |
| prism-data     | `/data`                          | DSH 配置及原生会话                                 |
| prism-projects | `/workspace`                     | 每个项目的独立目录、脱敏评估、知识记录和报告       |

先在页面创建项目，目录为 `/workspace/projects/<项目 UUID>`。主机管理员可将授权源码复制到相应目录：

```bash
docker compose cp ./my-project/. prism:/workspace/projects/<项目UUID>/
```

不开放从浏览器指定任意主机路径的功能。旧 `account.json` 不会被覆盖或自动导入；历史项目迁移应由管理员明确分配归属后导入，不能把旧共享目录直接当成全部用户的默认项目。

备份需要同时备份 PostgreSQL（如 pg_dump）以及另外两个卷；恢复应保持项目目录和 DSH 会话归属一致。`docker compose down` 保留卷，`down -v` 会删除数据，不应对需保留的数据执行。

## 模型、工具和访问地址

在 `.env` 配置现有 DSH 模型凭据，例如 `DEEPSEEK_API_KEY`，然后重新创建棱镜容器。没有模型凭据可以登录、管理项目和权限；实际模型任务需要可用模型。`.env` 不进入镜像。

容器默认含 Node、Python、Git、ripgrep；Nmap、Nuclei、Metasploit、Burp 需在派生镜像安装或由授权服务提供。不得为解决沙箱不可用而自动关闭沙箱或增加容器特权。

默认只映射 `127.0.0.1:3080`。改端口时同步设置 `PRISM_PORT` 和完整源 `PRISM_ORIGIN`。服务器 HTTPS 代理须保留 Host、Origin 并转发 WebSocket；HTTPS Cookie 带 Secure。修改初始密码后再开放远程入口。DSH 内核始终监听内部随机回环端口，其临时凭据不会发送给浏览器。

```bash
docker compose logs --tail=100 prism
docker compose restart prism
docker compose up -d --build
```

重置密码使用另一管理员的用户管理界面。没有可用管理员时由数据库管理员走受控恢复流程；启动不会恢复成 admin/admin，也不要删除数据库来解决密码问题。

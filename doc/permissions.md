# 角色、用户与资源权限

账号不绑定项目。用户可以没有任何角色，也可以组合多个角色；用户管理负责账号生命周期，权限管理负责角色与授权。功能模块可以直接使用，项目用于可选的归档、协作和资源授权。

## 独立使用功能

任务工作台、资产情况、漏洞汇总、工具集成均为一级入口。默认范围为“不关联项目 · 我的任务”，系统自动创建或恢复当前账号的原生任务记录，不要求手动创建项目或会话。在任一模块切换“查看范围”即可查看指定项目，模块保持不变；“新任务”用于开始另一条记录。

`task.use` 控制独立任务的查看与执行，普通用户默认角色包含此权限。独立任务仅本人及系统管理员可访问，普通用户不能通过猜测任务 ID、修改请求用户 ID、会话列表或审批事件访问他人记录。撤销该权限立即撤销访问，重新启动不会补回已撤销的角色授权。

数据库 `prism_personal_sessions` 只保存独立任务的归属和原生工作区信息，不创建隐含项目；聊天与执行仍由 DSH 处理。普通用户独立任务沿用受控工具边界。实际模型任务仍需要可用模型配置。

## 分配方式

1. 在“用户管理”创建账号，设置至少 8 位密码，无需选择项目。
2. 在“权限管理 → 角色权限”新建角色，选择系统功能，以及全部项目或指定项目的查看、执行、管理权限。
3. 在“用户授权”给账号分配一个或多个角色。
4. 对特殊情况添加用户例外：额外允许、明确拒绝，或移除例外恢复角色继承。

例如，“评估人员”角色可执行项目 A、只读项目 B。给某位用户添加“拒绝执行项目 A”，该用户仍能读取 A，但不能执行或管理 A；其他同角色用户不受影响。

## 判定规则

- 角色允许与用户额外允许合并，资源 `*` 表示该类全部资源（包括以后创建的项目）。
- 用户对某权限的明确拒绝优先于所有允许。管理隐含执行和查看，执行隐含查看；拒绝查看会同时阻止执行和管理，拒绝执行仍允许查看。
- 系统管理员拥有完整权限，不配置用户例外；角色不可编辑，至少保留一个启用管理员。
- 默认“普通用户”角色授予独立任务使用和创建项目。项目创建者得到可撤销的项目管理授权，`owner_id` 只记录创建者，不构成独立授权依据。
- 管理项目不包含管理角色、分配用户权限。账号管理也不自动包含角色授权管理。
- 更改用户角色会撤销其已有登录令牌；角色权限和用户例外变更立即使现有传输连接失效，后续请求重新检查权限。

## 持久化与升级

PostgreSQL 的 `prism_roles`、`prism_role_permissions`、`prism_user_roles`、`prism_user_permissions` 分别保存角色、角色权限、用户角色和用户例外；修改写入审计记录。DSH 继续负责会话内容。

升级时将旧管理员/普通用户身份转换为内置角色，将项目归属和成员权限一次性迁移为资源授权。`permissions-v1` 标记防止后续重启重新授予已撤销权限；旧成员表仅用于迁移，不再作为运行期授权来源，也不提供成员授权接口。

部署仍是单实例，执行隔离能力见 [容器部署](container.md)。
